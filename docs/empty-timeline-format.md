# Формат порожнього таймлайна

Наявний MCP-інструмент `resolve_lua_set_empty_timeline_fps` приймає додатковий
необов’язковий `resolution`: `1920x1080` або `3840x2160`. Наприклад:

```json
{
  "timeline_name": "Demo edit",
  "frame_rate": 60,
  "resolution": "3840x2160",
  "expected_project_id": "verified-native-project-id",
  "idempotency_key": "demo-empty-format-4k60",
  "confirm": true
}
```

Агент перевіряє порожність усіх відео-, аудіо- та субтитрових доріжок до резервної
копії та безпосередньо перед `SetSettings`. Потім зчитує fps, ширину й висоту
нативним API. Хибний readback не повертає успішну квитанцію. Зміна формату
використовує один сталий ключ; невизначений результат не повторюють з іншим ключем.
Виклик без `resolution` зберігає стару поведінку налаштування лише fps.

Роздільність вимагає нового нативного сеансу з capability
`empty_timeline_format_v1`. Постійний marker bundle містить збережений Lua-код:
оновлення Python/MCP саме по собі його не замінює. Старий нативний сеанс
відхиляється до резервування managed write key та публікації запиту. Не можна
додавати capability вручну до старого `session.json`; потрібна підготовка нового
сеансу з поточної встановленої версії та свіжа перевірка ідентичності проєкту.
Перезапуск процесу Resolve для цього не потрібний.

Звичайний `resolve_lua_prepare_render` використовує фіксований профіль 1080p.
Для 4K застосовують `resolve_prepare_render_job` з профілем
`youtube-2160p-h264-v1`, лише якщо його підтвердив поточний нативний backend.
