# Рендер через MCP: час очікування та помилки

`resolve_get_render_options` і `resolve_prepare_render_job` типово очікують
відповідь до 300 секунд. Lua-транспорт виконує кілька послідовних звернень до
нативного SDK: отримання всіх форматів може перевищувати 30 секунд, навіть коли
читання таймлайна працює. Параметр `timeout_seconds` дозволяє змінити цей час.
Збільшення часу очікування не запускає рендер і не перемикає протокол після
відправлення команди.

Успішні відповіді зберігають попередню структуру. Очікувані помилки повертають
`isError: true`, `code`, `detail` та `retryable`: зокрема, неправильні аргументи
й відсутній пресет Resolve. Помилка перевірки підключення також містить
`phase: readiness` і `outcome: not_dispatched` — команда рендера ще не надіслана.

`COMMAND_TIMEOUT` містить `command_id`, `timeout_seconds`, початковий
`idempotency_key` для поставленої в чергу команди та `outcome: unverified`.
Таймаут не доводить, що підготовка не відбулася: Resolve може завершити її
й додати завдання пізніше. Перед повторенням перевір початкову відповідь або
квитанцію. Збережи той самий ключ; новий ключ може створити зайве завдання.
Обробник помилок MCP самостійно не повторює підготовку після таймауту.

Для попередньої інсталяції можна явно задати час, наприклад
`resolve_get_render_options(timeout_seconds=180)`. Для підготовки збережи
початкові аргументи й ключ та задай достатній час очікування. Спершу з'ясуй
результат попереднього запиту, якщо він уже завершився таймаутом.
