# Автоматичне підключення Resolve Free

Керований автозапуск прибирає щоденний ручний запуск **Resolve Agent Marker**.
Фоновий помічник у Windows чекає, доки ти відкриєш збережений проєкт у Resolve,
запускає встановлений міст через його пункт меню й перевіряє відповідь самого
Resolve. Кілька MCP-чатів можуть використовувати один профіль підключення.

Це окремий режим, який потрібно явно ввімкнути. Звичайне підключення з
`--runtime` продовжує працювати за [ручною інструкцією](free-startup.md).

## Як це виглядає щодня

1. Запускаєш Resolve звичайною іконкою.
2. Відкриваєш потрібний наявний збережений проєкт самостійно або доручаєш
   [точне відкриття з Project Manager](open-existing-project.md).
3. Помічник запускає міст. Натискати **Workspace → Scripts** не потрібно.
4. У чаті просиш перевірити свіже з’єднання й назву проєкту, після чого
   переходиш до погоджених монтажних дій.

Якщо Resolve залишився в Project Manager, фоновий помічник чекає. Для явного
відкриття є окрема команда `resolve_free_open_project`: вона потребує точних
назв бібліотеки й проєкту, відомого UUID та твого підтвердження. Довільного
вибору бібліотеки чи проєкту за схожою назвою немає.
Вікно Resolve має бути доступним у розблокованому сеансі Windows. Для меню
використовується фіксований адаптер англійського інтерфейсу Resolve;
неоднозначні вікна, сторонній діалог або недоступний пункт меню зупиняють запуск.

Автозапуск використовує той самий готовий скрипт меню, що й ручний режим.
Він не потребує Computer Use у чаті, Lua-консолі, зовнішнього scripting API
Studio або довготривалого циклу через `fusion:Execute()`.

## Відкрити проєкт із Project Manager

У керованому підключенні команда `resolve_free_open_project` доступна,
навіть коли нативний міст ще не підключений. Вона відкриває один точний
наявний проєкт, після чого помічник запускає міст і перевіряє свіжу відповідь
Resolve: бібліотеку, кореневу папку, назву й UUID.

Спочатку один раз відкрий проєкт самостійно й отримай його UUID через
`resolve_free_connection_status`. Збережи цей UUID разом із точною назвою
проєкту й бібліотеки для наступних запусків. Наразі команда підтримує лише
корінь локальної бібліотеки (`Disk`, `folder_path: []`). Приклади запиту,
JSON і CLI — в [окремій інструкції](open-existing-project.md).

Внутрішній сервіс перевірено в одному профілі: Windows 10 Education build
19045, Python 3.12.10, Resolve Free 21.1.2.10. Після перезапуску Resolve він
знайшов проєкт у Project Manager, перевірив його UUID і назву через приватний
експорт `.drp`, відкрив його, автоматично запустив міст і отримав свіже нативне
підтвердження бібліотеки, кореневої папки та UUID. Повна перевірка цієї команди
через встановлений MCP ще триває; інші середовища не вважаються перевіреними.

Поточний шлях підтримує одну зареєстровану й вибрану локальну `Disk` бібліотеку,
користувача `guest` і всі проєкти в корені. Якщо структура бібліотеки або
елементи інтерфейсу не підтримуються чи неоднозначні, команда зупиняється з
кодом причини. Computer Use її не підміняє; проєкт можна відкрити вручну.

## Налаштування один раз

Спочатку [встанови агент](../README.md#1-установи-агент). Нижче використано
приклади шляхів; заміни їх власними абсолютними шляхами. Усі чати, які мають
працювати з цим Resolve, повинні посилатися на **той самий файл профілю**.

### 1. Створи профіль

Папка `runtime_base` зберігатиме службові сеанси й локальні експорти проєкту.
`media_roots` перелічує вже наявні папки, з яких дозволено імпортувати медіа.
Це не папки, які помічник має автоматично імпортувати.

```powershell
New-Item -ItemType Directory -Path C:/DaVinciAgent/runtime -Force | Out-Null
@'
{
  "schema": 1,
  "enabled": true,
  "runtime_base": "C:/DaVinciAgent/runtime",
  "media_roots": ["C:/VideoAssets"]
}
'@ | Set-Content -LiteralPath C:/DaVinciAgent/autostart.json -Encoding utf8
```

Папка `C:/VideoAssets` у прикладі має вже існувати. Збережи профіль у постійній
локальній папці: поряд із ним агент зберігає стан підключення й належність
незавершених операцій. Не використовуй одну папку стану для різних профілів.

### 2. Підключи MCP до профілю

У конфігурації MCP-клієнта заміни статичний `--runtime` на `--managed-profile`:

```toml
[mcp_servers.davinci-resolve]
command = 'C:/Tools/DaVinci-Resolve-Agent/.venv/Scripts/davinci-agent-mcp.exe'
args = ["--backend", "free-marker", "--managed-profile", "C:/DaVinciAgent/autostart.json"]
cwd = 'C:/Tools/DaVinci-Resolve-Agent'
startup_timeout_sec = 30
tool_timeout_sec = 650
default_tools_approval_mode = "writes"
required = false
```

Онови MCP-підключення після зміни конфігурації. Уже запущений сервер зі старим
`--runtime` сам не стане керованим сервером. Надалі файл профілю залишається
сталим, а нові сеанси після перезапуску Resolve вибирає агент.

Для додаткових команд налаштування звуку можна окремо додати
`--enable-windows-recording-ui`. Цей прапорець не потрібен для самого автозапуску
мосту й не запускає запис.

### 3. Увімкни фоновий помічник

Виконай з папки встановленого агента:

```powershell
.\.venv\Scripts\python.exe -m agent.resolve_watch `
    --profile C:/DaVinciAgent/autostart.json --install-autostart
.\.venv\Scripts\python.exe -m agent.resolve_watch `
    --profile C:/DaVinciAgent/autostart.json --start
```

Перша команда додає керований ярлик до автозавантаження поточного користувача
Windows. Друга запускає помічник зараз у фоні, без видимого термінала.
Завдяки автозавантаженню міст зможе підключитися й тоді, коли Resolve запущено
раніше за MCP-клієнт. Самого запису сервера в MCP-конфігурації для цього
недостатньо.

Якщо залишився старий `ResolveAgentStartup.scriptlib`, створений експериментальним
launcher цього агента, встановлення переносить його в `legacy-startup` поряд
із профілем і зберігає як резервну копію. Це прибирає конкуруючий спосіб запуску.
Сторонні скрипти не змінюються. Команда `--remove-autostart` не відновлює цей
старий hook автоматично.

Якщо Resolve був відкритий ще до першого встановлення пункту меню, збережи
роботу й один раз перезапусти застосунок, щоб він побачив новий скрипт.
Помічник сам не закриває й не перезапускає Resolve.

Для явного запуску помічника в поточному терміналі:

```powershell
.\.venv\Scripts\python.exe -m agent.resolve_watch `
    --profile C:/DaVinciAgent/autostart.json
```

### 4. Перевір з’єднання

Відкрий наявний збережений проєкт і попроси в чаті:

> Перевір `resolve_free_autostart_status`, потім свіже з’єднання через
> `resolve_free_connection_status`. Покажи назву та UUID відкритого проєкту.

Стан помічника показує, на якому кроці він зупинився. Наявність процесу Resolve,
правильного заголовка вікна або поновленого lease ще не доводить підключення.
Для роботи з медіа потрібна нова відповідь нативного мосту з назвою та UUID.

## Після перезапуску Resolve

Для нового процесу Resolve агент створює новий незмінний сеанс. Старі експорти,
резервні копії та результати операцій залишаються на місці. MCP-сервер вибирає
один сеанс на всю операцію, включно з резервною копією й перевіркою результату.

Якщо відповідь на зміну втрачено, збережи її початкові параметри та
`idempotency_key`. Ключ із попереднього сеансу не виконає ту саму зміну в новому:
агент поверне відомості про початковий сеанс для перевірки результату.
Незавершені або пошкоджені записи операцій блокують ротацію, доки їх не
перевірено. Новий ключ не є способом відновлення невизначеної зміни.

Явна зупинка мосту, помилка Lua або невизначений результат запуску не
спричиняють повторного натискання пункту меню. Помічник не перезапускає
вже завершений сеанс і не закриває Resolve примусово.

## Кілька чатів

Використовуй один профіль для всіх чатів, які керують одним екземпляром Resolve.
Фоновий помічник має одного власника; MCP-чати читають спільний активний сеанс.
Зміни потрібно узгоджувати між чатами: спільне підключення не робить паралельні
монтажні доручення незалежними.

Якщо інша операція займає канал, дочекайся її результату й повтори читання
стану. Для невизначеного запису зберігай початковий ключ та перевіряй саме його
результат. Не видаляй lock-файли, inbox або квитанції, щоб «звільнити» канал.

## Перевірити стан без звернення до Resolve

```powershell
.\.venv\Scripts\python.exe -m agent.resolve_watch `
    --profile C:/DaVinciAgent/autostart.json --status
```

Ця команда читає збережений стан. Вона не запускає скрипт і не є свіжою
перевіркою native-з’єднання.

Дивись насамперед на `state` і `watcher_health`. Поле `active.phase` зберігає
стан останнього активного сеансу; навіть значення `connected` може залишитися
там після зупинки помічника. `recent_heartbeat` означає лише, що помічник
нещодавно оновив свій статус. Назва й UUID у попередньому native-підтвердженні
також є історичними даними, доки новий запит не підтвердить поточне з’єднання.

Типові причини очікування:

| Стан | Що перевірити |
| --- | --- |
| `watcher_status_unknown` | Статус помічника ще не записаний. Перевір його запуск через `--start`, потім повтори `--status`. Це не означає, що Resolve закритий. |
| `watcher_stale` | Помічник давно не оновлював статус. Перевір його процес і `watcher.log` поряд із профілем; не покладайся на старий `active.phase`. |
| `watcher_status_invalid` / `active_state_invalid` | Збережений стан неможливо надійно прочитати. Збережи діагностику й перевір ці файли перед подальшою роботою; не видаляй старі сеанси та результати операцій. |
| `disabled` | У профілі вимкнено автозапуск. Якщо він потрібен, увімкни `enabled` і перезапусти фоновий помічник із цим профілем. |
| `operation_busy` | Канал займає інший чат або помічник. Дочекайся завершення операції й повтори перевірку; lock-файли видаляти не потрібно. |
| `resolve_absent` | Запусти Resolve звичайним способом. |
| `waiting_project` | Відкрий потрібний наявний збережений проєкт або скористайся окремою командою відкриття з її обмеженнями. Якщо проєкт уже відкритий, розблокуй Windows і закрий сторонній діалог. |
| `installation_failed` / `dispatch_failed` | Збережи діагностику; перевір встановлений пункт меню й англійський інтерфейс Resolve. |
| `dispatch_retry_wait` | Адаптер підтвердив, що запуск скрипта ще не відбувся. Помічник може повторити спробу в межах початкового часу запуску. Невизначений результат виконання так не повторюється. |
| `awaiting_native` | Помічник чекає на відповідь мосту в межах часу запуску. |
| `dispatch_unverified` | Підтвердження запуску не отримано. Збережи діагностику: скрипт міг уже почати роботу, тому повторного натискання немає. |
| `recovery_required` | Перевір початкову операцію; збережи її параметри, ключ і старий runtime. |
| `connected` | Підтвердь свіжу назву та UUID перед погодженими змінами: збережений статус сам не доводить поточне з’єднання. |

## Прибрати запуск під час входу у Windows

```powershell
.\.venv\Scripts\python.exe -m agent.resolve_watch `
    --profile C:/DaVinciAgent/autostart.json --remove-autostart
```

Команда прибирає лише власний керований ярлик. Уже запущений помічник і міст
продовжують працювати; видалення ярлика не видаляє профіль, проєкти чи runtime.

## Межі перевірки

Автозапуск керує лише запуском мосту. Він не налаштовує мікрофон, обробку звуку,
армування, імпорт або запис. Відкриття проєкту з Project Manager виконується
окремою підтвердженою командою, описаною в
[посібнику відкриття проєкту](open-existing-project.md).
Наявність автоматизованих тестів не підтверджує доступність меню в конкретній
інсталяції Resolve. Живий запуск, перезапуск застосунку та повторне підключення
кількох чатів потрібно перевіряти окремо й фіксувати в
[матриці сумісності](manual-integration-testing.md).
