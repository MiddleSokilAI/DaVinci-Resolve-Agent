# Відкрити наявний проєкт із Project Manager

У керованому режимі `--managed-profile` інструмент `resolve_free_open_project`
доступний, навіть коли Resolve показує Project Manager і нативний міст ще не
підключений. Він призначений для одного заздалегідь відомого збереженого проєкту.

Повний шлях від Project Manager через вибір проєкту й автоматичний запуск мосту
до свіжого нативного підтвердження **перевірено в одному профілі**: Windows 10
Education build 19045, Python 3.12.10, Resolve Free 21.1.2.10. Цей повний шлях
перевірено через внутрішній сервіс агента. Через встановлений MCP окремо
перевірено вже відкритий проєкт: свіже підключення, збіг повного контексту без
повторного Open, безпечний повтор того самого ключа й нове незалежне
підключення. Повний старт із Project Manager через встановлений MCP ще не
повторювали. Інші середовища не вважаються перевіреними. Якщо агент не може
однозначно перевірити бібліотеку, вибраний проєкт або потрібні елементи Windows
UI Automation, він повідомить код причини й зупиниться. Точний обсяг перевірки
наведено в [матриці сумісності](manual-integration-testing.md).

## Підготуй дані один раз

1. [Налаштуй кероване підключення](managed-autostart.md) з `enabled: true`.
2. Відкрий потрібний збережений проєкт самостійно, дочекайся запуску мосту й
   попроси перевірити `resolve_free_connection_status`.
3. Збережи повернуті точну назву й `project.id` — це UUID проєкту.
   Також зафіксуй точну назву його бібліотеки.

UUID не вгадується за назвою проєкту. Для відкриття потрібні всі три значення:
бібліотека, назва проєкту та його раніше перевірений UUID. Назва бібліотеки має
збігатися з її `DbName` у Resolve API; довільні псевдоніми автоматично не підбираються.

Наразі автоматичне відкриття підтримує обмежену конфігурацію:

- У локальному переліку Resolve зареєстрована рівно одна бібліотека — вибрана
  локальна `Disk`, назва якої точно збігається з переданим `DbName`.
- Бібліотека використовує користувача `guest`; **усі її проєкти перебувають у
  корені**, без папок. `folder_path` має бути порожнім масивом `[]`.
- У бібліотеці не більше 128 проєктів. Назва потрібного проєкту не повинна
  збігатися з іншою назвою або бути її частиною: пошук має залишити один
  однозначний результат.
- Структура збережених проєктів відповідає відомому профілю схеми 17,
  дослідженому на файлах Resolve 21.1.2. Інші схеми автоматично не приймаються.

Вкладені папки, інші користувачі бібліотеки, кілька зареєстрованих бібліотек,
PostgreSQL та хмарні бібліотеки поки не підтримуються цим шляхом. Можна відкрити
потрібний проєкт вручну й далі користуватися звичайним керованим підключенням.

## Попроси відкрити проєкт

Запусти Resolve звичайною іконкою та залиш Project Manager доступним у
розблокованому сеансі Windows. Після цього напиши в чаті, наприклад:

> Відкрий уже наявний проєкт «Навчальний проєкт» у корені локальної бібліотеки
> «Demo Library». Його перевірений UUID — `00000000-0000-4000-8000-000000000001`.
> Підтверджую відкриття. Використай ключ `open-training-project-001`.
> Покажи свіжу перевірку бібліотеки, папки, назви та UUID. Запис не запускай.

Назви, UUID та ключ у цьому прикладі вигадані. Заміни їх своїми перевіреними
даними. Для одного доручення зберігай той самий `idempotency_key`, включно з
повторними зверненнями після втрати відповіді.

Аргументи інструмента `resolve_free_open_project`:

```json
{
  "project_name": "Навчальний проєкт",
  "expected_project_id": "00000000-0000-4000-8000-000000000001",
  "expected_database": {
    "DbType": "Disk",
    "DbName": "Demo Library"
  },
  "folder_path": [],
  "idempotency_key": "open-training-project-001",
  "confirm": true,
  "timeout_seconds": 120
}
```

Команда потребує явного `confirm: true`. Вона використовує фіксований Windows
UI Automation адаптер усередині агента. Computer Use, OCR, керування довільними
координатами чи введення довільних команд у консоль для цього не застосовуються.

Спочатку агент читає локальний перелік бібліотек і перевіряє збережені проєкти
через приватні копії їхніх файлів. SQLite працює тільки з цими копіями; живі
бази Resolve не відкриваються через SQL і не змінюються. Потім адаптер вводить
точну назву в пошук Project Manager за полем **Name** та експортує вибраного
кандидата в окремий приватний `.drp`. Його UUID і назва мають точно збігтися з
дорученням. Сам текст пошуку або виділення рядка не дає дозволу натиснути Open.

Під час цієї перевірки може автоматично з’явитися стандартне вікно
Save/Export — це очікуваний крок експорту кандидата. Не втручайся в нього й
залиш мишу та клавіатуру без дій до відповіді агента. Файл `.drp` зберігається
локально в `project-open-evidence` поруч із файлом керованого профілю. Це
службовий приватний файл: він не публікується й не завантажується назовні;
не додавай його до PR або публічного звіту.

Безпосередньо перед Open агент знову звіряє поточний сеанс Resolve, пошук,
експортований файл і стан бібліотеки. Зміна введення користувачем або втрата
підтвердження зупиняє автоматичну дію.

Після точного відкриття агент запускає міст відповідного сеансу й отримує нову
відповідь Resolve API. Перевіряються поточна бібліотека, коренева папка, єдина
точна назва проєкту в цій папці та UUID відкритого проєкту. Самого натискання
Open або заголовка вікна для повідомлення про успіх недостатньо.

Успішний свіжий результат має `context_verified: true`,
`folder_membership_verified: true`, `native_connection_verified: true` та
`proof_scope: "fresh_native_context"`. Після цього можна переходити до окремо
погоджених дій із проєктом.

Якщо потрібний проєкт уже відкритий і повний нативний контекст збігається,
команда перевіряє його без повторного відкриття. Інший відкритий проєкт не
перемикається мовчки.

## Запуск із PowerShell

Виконай з папки встановленого агента, використовуючи той самий профіль, що й MCP:

```powershell
.\.venv\Scripts\python.exe -m agent.resolve_watch `
    --profile C:/DaVinciAgent/autostart.json `
    --open-project "Навчальний проєкт" `
    --expected-project-id "00000000-0000-4000-8000-000000000001" `
    --database-name "Demo Library" `
    --idempotency-key "open-training-project-001" `
    --confirm `
    --project-open-timeout 120
```

Ця команда не запускає сам застосунок Resolve. Його потрібно відкрити
заздалегідь. Прапорець `--enable-windows-recording-ui` для відкриття проєкту
не потрібен.

## Якщо відповідь втрачена або перевірка не пройшла

Відкриття могло вже відбутися. Повтори **той самий запит із тими самими
параметрами й ключем**: агент перевірятиме початковий результат і не натискатиме
Open повторно. Не змінюй ключ, не видаляй службові записи й не створюй інший
сеанс, щоб обійти невизначений результат. Незавершене відкриття блокує нові зміни
проєкту до перевірки його контексту.

Повтор завершеної команди може повернути збережений результат із
`proof_scope: "historical_completed_receipt"`. Це підтвердження попередньої
операції; перед новими змінами попроси свіжу перевірку з’єднання.

Якщо повідомлено `OPERATION_BUSY`, дочекайся поточної операції та повтори запит
із тим самим ключем. Помилки сумісності інтерфейсу, зокрема
`COMPATIBILITY_UNVERIFIED`, потребують перевірки адаптера на цьому інтерфейсі.
Автоматичної заміни через Computer Use або вибору схожої назви немає.

Невідома структура бібліотеки чи схеми, дублікати назв або UUID, файли
`-wal`, `-shm`, `-journal` біля баз проєктів або зміна джерел під час читання
також зупиняють операцію з кодом причини. Агент не видаляє ці файли й не
перебудовує бібліотеку. Відкриття проєкту вручну залишається доступним; після
нього дочекайся мосту й попроси свіжу нативну перевірку контексту.

Після оновлення агента вже запущений міст може ще не мати нової перевірки
контексту. Для неї потрібен новий сеанс. Спочатку перевір незавершені операції
й збережи поточну роботу, потім підготуй новий запуск Resolve у керованому режимі.

Команда не створює та не імпортує проєктів, не скидає базу даних, не зберігає
чужий відкритий проєкт і не запускає відтворення або запис. Межі живої перевірки
фіксуються в [матриці сумісності](manual-integration-testing.md).
